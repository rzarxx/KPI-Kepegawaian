01 · Konsep inti

Bagaimana data penilaian disimpan

Satu hasil penilaian tidak hanya menempel ke nama karyawan. Sistem menyimpan konteks lengkap agar histori tetap dapat ditelusuri.

KaryawanIdentitas permanen
→
PenempatanCabang, divisi, subdivisi
→
PeriodeRentang penilaian
→
PenilaiAkun pembuat draf
→
HasilNilai, kriteria, status

Kunci logika saat ini

Satu karyawan, satu identitas

Mutasi, resign, atau terminasi tidak menghapus identitas. Riwayat organisasi disimpan pada penempatan karyawan.

Penilaian per penilai

Kombinasi uniknya adalah karyawan + periode + penilai. Dua penilai dapat menghasilkan dua penilaian terpisah untuk orang dan periode yang sama.

Snapshot penempatan

Saat draf disimpan, ID penempatan aktif ikut disimpan. Ini mempertahankan konteks organisasi pada waktu penilaian.

Komponen berbasis data

Nama, bobot, metode, dan aturan nilai tidak ditanam langsung di kolom karyawan; semuanya berasal dari konfigurasi komponen.

Apa arti “per divisi”?Karyawan masuk ke divisi melalui penempatan aktif. Kepala Divisi hanya dapat melihat dan memproses karyawan yang penempatan aktifnya cocok dengan scope cabang dan divisi akun tersebut. Akses URL langsung di luar scope menghasilkan 403.

Siapa melakukan apa

RoleCakupanTindakan penilaian utamaTindakan lain
Super AdminSeluruh organisasiBuat, ubah, ajukan, setujui, finalisasiSemua konfigurasi, pengguna, audit, impersonasi
HR AdminMenurut scope; akun UAT globalBuat, ubah, ajukanKelola karyawan, organisasi, dokumen, laporan
HR ManagerMenurut scope; akun UAT globalSetujui dan finalisasiLaporan, ekspor, audit baca
Kepala CabangSatu cabangSetujuiLihat/ubah karyawan, insiden, laporan dan ekspor
Kepala DivisiSatu cabang + satu divisiBuat, ubah, ajukan, setujuiInsiden, laporan baca

Urutan pemeriksaan keamananAutentikasi → permission → policy → organizational scope → validasi → aturan bisnis → audit log.

Scope lebih kuat daripada filter

Filter cabang/divisi membantu mencari data, tetapi bukan batas keamanan. Server lebih dulu membatasi dataset sesuai scope akun. Karena itu, Kepala Divisi SDM Jakarta tidak dapat membuka karyawan Operasional Jakarta atau Surabaya meskipun mengganti URL atau parameter filter.

Catatan tata kelolaSecara izin teknis, Kepala Divisi dapat mengajukan sekaligus menyetujui penilaian dalam scope sendiri. Jika organisasi mensyaratkan prinsip empat mata, gunakan SOP: Kepala Sub Divisi mengisi/mengajukan, Kepala Divisi menyetujui, lalu HR Manager memfinalisasi.

03 · Persiapan data

Urutan sebelum mulai menilai

  1. Masuk menggunakan akun aktif dan terverifikasi.
  2. Periksa badge role dan cakupan pada bagian kanan atas.
  3. Pastikan struktur pada menu Organisasi sudah berisi cabang, divisi, subdivisi, dan jabatan.
  4. Pastikan karyawan mempunyai penempatan aktif. Tanpa penempatan aktif, penilaian tidak dapat disimpan.
  5. Pastikan periode dan komponen penilaian sudah disiapkan.

Membuat atau memeriksa karyawan

Tambah karyawan

Menu Karyawan → Tambah Karyawan. Isi nomor karyawan, identitas, tanggal bergabung, cabang, divisi, subdivisi, jabatan, dan status awal.

Cari per divisi

Di menu Karyawan, pilih Cabang → Divisi → Sub Divisi bila diperlukan, lalu tekan Terapkan.

Aturan penempatan

  • Nilai Masa Kerja memakai tanggal bergabung karyawan, bukan tanggal pembuatan akun.
  • Scope memakai penempatan aktif; untuk karyawan nonaktif tanpa penempatan aktif, daftar dan laporan dapat memakai penempatan terakhir.
  • Mutasi harus dilakukan melalui fungsi mutasi agar riwayat penempatan lama tetap tersimpan.
  • Kepala Divisi/Sub Divisi tidak dapat memilih atau melihat data organisasi di luar scope efektifnya.
Jangan mulai penilaian bila penempatan salahPenilaian menyimpan snapshot ID penempatan aktif. Perbaiki penempatan terlebih dahulu agar histori divisi pada hasil penilaian benar.

05 · Mengisi performa

Langkah pengisian nilai karyawan

Syarat akunGunakan HR Admin, Kepala Divisi, atau Kepala Sub Divisi yang memiliki permission membuat penilaian. Karyawan target harus berada dalam scope akun.
  1. Buka menu Karyawan.
  2. Pilih filter Cabang dan Divisi untuk membentuk daftar kerja per divisi.
  3. Catat ID karyawan dari URL halaman detail, misalnya /karyawan/12.
  4. Buka menu Penilaian, tentukan periode berstatus Aktif, dan catat ID periodenya dari data/route yang tersedia.
  5. Sampai tombol navigasi dibuat, buka /penilaian/12/3 dengan format /penilaian/{id-karyawan}/{id-periode}.
  6. Isi semua komponen manual dengan nilai 0–100. Komponen Masa Kerja akan dihitung oleh server.
  7. Isi catatan penilaian bila diperlukan.
  8. Tekan Simpan Draf. Server menghitung ulang total dan kriteria.
  9. Periksa ringkasan, lalu tekan Ajukan Penilaian jika data sudah benar.
Batasan navigasi build saat iniID periode belum ditampilkan sebagai alat operasional di UI dan tidak ada tombol Mulai Penilaian. Penggunaan URL manual cocok untuk UAT teknis, belum ideal untuk operator produksi. Pengembangan berikutnya sebaiknya menambahkan daftar periode aktif serta tombol Mulai/Lanjutkan Penilaian pada detail karyawan.

Validasi yang dilakukan server

  • Karyawan harus berada dalam scope penilai dan memiliki penempatan aktif.
  • Periode harus dapat digunakan dan komponen aktif harus berbobot total 100%.
  • Semua komponen manual wajib dinilai; nilai harus 0–100.
  • Draf yang sudah diajukan tidak dapat diedit.
  • Setiap penyimpanan dan perubahan status dicatat di audit log.

06 · Perhitungan

Cara total nilai dihitung

Setiap komponen menghasilkan nilai mentah 0–100. Nilai tertimbang adalah nilai mentah dikalikan bobot. Total akhir merupakan jumlah seluruh nilai tertimbang.

nilai_tertimbang = nilai_mentah × (bobot / 100)
total_akhir = Σ seluruh nilai_tertimbang

Contoh

KomponenNilaiBobotHasil tertimbang
Masa Kerja8510%8,50
Tanggung Jawab9020%18,00
Absensi8020%16,00
Inisiatif7510%7,50
Sikap8815%13,20
Komunikasi8210%8,20
Kerjasama Tim8615%12,90
Total84,30

Total 84,30 masuk kriteria Sangat Baik.

SOP yang disarankan

  1. Kepala Sub Divisi mengisi data berdasarkan bukti kerja, absensi, dan observasi periode.
  2. Kepala Sub Divisi mengajukan draf.
  3. Kepala Divisi meninjau keselarasan antar tim dan menyetujui.
  4. HR Manager memeriksa kepatuhan kebijakan serta memfinalisasi.
  5. Setelah periode selesai dan koreksi administratif tuntas, HR Manager menutup penilaian.
Tidak ada alur mundurImplementasi saat ini hanya mengizinkan status maju satu tahap. Belum ada fungsi “Kembalikan ke Draf” atau “Tolak”. Koreksi harus dilakukan sebelum pengajuan.

08 · Operasi per divisi

Menjalankan satu siklus penilaian

A. Administrator HR

  • Pastikan semua karyawan mempunyai penempatan aktif dan tanggal bergabung benar.
  • Periksa total bobot komponen 100%.
  • Buat periode, lalu aktifkan.
  • Pastikan role dan scope kepala unit sudah benar.

B. Kepala unit

  • Periksa badge cakupan saat login.
  • Filter daftar Karyawan berdasarkan divisi/subdivisi.
  • Isi satu draf per karyawan yang menjadi tanggung jawabnya.
  • Verifikasi total dan catatan sebelum mengajukan.

C. Penyetuju

  • Pastikan hasil yang dibuka masih dalam scope.
  • Bandingkan hasil antar karyawan dengan bukti objektif.
  • Setujui hanya setelah semua komponen diperiksa.

D. HR Manager

  • Finalisasi penilaian yang sudah disetujui.
  • Periksa tren dan kriteria di Beranda.
  • Filter Laporan per cabang/divisi dan ekspor bila dibutuhkan.
  • Tutup penilaian setelah siklus administrasi berakhir.
Jika karyawan dimutasi di tengah periodePenilaian memakai penempatan aktif saat draf disimpan. Tentukan kebijakan internal apakah penilai berasal dari unit lama atau unit baru sebelum menyimpan draf. Sistem belum membagi satu periode secara prorata antar penempatan.
Hindari penilaian ganda yang tidak disengajaKarena setiap penilai dapat membuat rekornya sendiri, tetapkan satu penilai utama per karyawan/periode. Sistem belum menggabungkan atau merata-ratakan beberapa penilai secara otomatis.

09 · Laporan

Melihat hasil dan mengekspor data

Beranda

Ringkasan, rata-rata, tren, dan aktivitas penilaian di Beranda hanya memakai status Final dan Ditutup. Filter periode/cabang/divisi/subdivisi tetap tunduk pada scope pengguna.

Menu Laporan

Filter tersedia untuk tanggal, cabang, divisi, subdivisi, status karyawan, kriteria hasil, dan status masalah. Tabel menampilkan hasil penilaian terbaru yang cocok pada relasi karyawan.

Perbedaan Beranda dan LaporanBeranda secara eksplisit membatasi penilaian Final/Ditutup. Query Laporan saat ini tidak memfilter status penilaian, sehingga penilaian terbaru yang tampil dapat masih Draf/Diajukan/Disetujui. Periksa status dari detail/audit sebelum menjadikan laporan sebagai hasil resmi.

Ekspor XLSX

  1. Terapkan filter laporan.
  2. Tekan Ekspor XLSX.
  3. Job masuk ke queue dengan status Menunggu Antrean.
  4. Queue worker membuat file privat.
  5. Unduh dari Riwayat Ekspor ketika status Siap Diunduh.
Prasyarat operasionalQueue worker harus berjalan. File ekspor disimpan privat dan kedaluwarsa setelah 24 jam. Pengguna hanya dapat mengunduh ekspor miliknya sendiri dan scope pada saat permintaan disimpan sebagai snapshot.

Akun dan data demonstrasi

Seeder lokal membuat akun portal untuk semua role kecuali Karyawan. Gunakan hanya pada lingkungan local atau testing.

Password berasal dari LOCAL_ROLE_SEED_PASSWORD. Bila variabel tidak diatur, fallback lokal seeder adalah KpiLokal2026!. Jangan gunakan kredensial ini pada production.

Data organisasi UAT

  • Cabang UAT Jakarta: SDM Jakarta dan Operasional Jakarta.
  • Cabang UAT Surabaya: Operasional Surabaya.
  • Karyawan UAT ditempatkan pada Administrasi SDM, Rekrutmen, Lapangan Jakarta, dan Lapangan Surabaya.

Skenario pengecekan scope

  1. Login sebagai Kepala Divisi; pastikan hanya karyawan SDM Jakarta yang terlihat.
  2. Coba membuka URL karyawan Operasional/Surabaya; hasil wajib 403.
  3. Login sebagai Kepala Sub Divisi; pastikan hanya Administrasi SDM yang terlihat.
  4. Login sebagai Kepala Cabang; pastikan seluruh divisi Jakarta terlihat, tetapi Surabaya tidak.

Checklist sebelum periode ditutup

  • Tidak ada draf yang tertinggal.
  • Semua penilaian resmi sudah Final.
  • Scope penyetuju sudah diverifikasi.
  • Laporan per cabang/divisi sudah diperiksa.
  • Ekspor final sudah selesai dan dapat dibuka.
  • Catatan koreksi administratif sudah ditutup.
Rangkuman satu kalimatSiapkan organisasi dan periode → filter karyawan sesuai divisi → isi semua nilai manual → simpan draf → ajukan → setujui → finalisasi → periksa Beranda/Laporan → tutup.
